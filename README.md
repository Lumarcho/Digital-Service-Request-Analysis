# Digital-Service-Request-Analysis
**Project Overview**

This personal business analysis project explores the design of a digital service request management process.

The concept is based on a common organisational problem: service requests being submitted through different channels without a consistent process for recording, assigning, tracking and closing requests.

**Business Problem**

A fragmented service request process can result in:

Poor visibility of outstanding requests
Delayed responses
Duplicate requests
Limited accountability
Difficulty tracking performance
Inconsistent communication with users

**Proposed Solution**

The proposed solution is a centralised digital service request system where users can submit requests and organisations can track each request from submission through to resolution.

**Key Stakeholders**

End Users
Service Desk / Support Team
Team Leaders
Operations Management
System Administrator
Business Analyst
IT Development Team

**Example Requirements**

**Functional Requirements**
Users should be able to submit service requests.
Users should receive a request reference number.
Support staff should be able to assign requests.
Users should be able to view request status.
Support staff should be able to update request status.
Management should be able to view service performance reports.

**Non-Functional Requirements**

The system should be easy to use.
User information should be protected.
The system should provide reliable access.
Requests should be traceable throughout their lifecycle.

**Example User Story**

As a user, I want to submit a service request online so that I can receive a reference number and track its progress.

**Acceptance Criteria**

A user can submit a valid request.
The system generates a unique reference number.
The request is recorded in the system.
The user can view the request status.
